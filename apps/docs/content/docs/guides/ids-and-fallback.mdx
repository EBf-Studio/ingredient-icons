## Ids

Every icon is named after an id of Marmalade's ingredient catalog: the ingredient's English name in kebab-case. The package ships a snapshot of the catalog, `catalog.json`, with <CatalogSize /> entries: each has its parent, its family and its [names](/docs/guides/names).

| Ingredient | Id | File |
| --- | --- | --- |
| Shallot | `shallot` | `shallot.webp` |
| Crème fraîche | `creme-fraiche` | `creme-fraiche.webp` |
| Black pepper | `black-pepper` | `black-pepper.webp` |

A file is named after its id, nothing more.

### Families

<FamilyCount /> entries have no parent: they are the families, such as `vegetables`, `cheeses` or `spice-blends`. Every other entry is a catalog ingredient, with exactly one parent (another ingredient or a family) and one family, the one at the top of its parents.

```json title="catalog.json (excerpt)"
"shallot": { "parent": "onion", "family": "vegetables", "names": { … } },
"onion": { "parent": "vegetables", "family": "vegetables", "names": { … } },
"vegetables": { "names": { … } }
```

Every family has its own icon (the pack's checks refuse a release otherwise), so a walk up the parents always ends on something close.

### Getting ids for your ingredients

- **Map your ingredient list once.** Search `catalog.json` by name or synonym, in any of its six languages, and store the id with each ingredient. The [gallery](/icons) shows the id of every icon, and the [home page](/) finds any catalog ingredient by name.
- **Store the most precise id.** `extra-virgin-olive-oil` rather than `olive-oil`: it shows the olive oil icon today, and its own if one is drawn later.
- **An ingredient the catalog lacks?** Ask for it: it is added to the catalog first, then drawn. See [Requesting icons](/docs/requesting-icons).

## Fallback

`iconUrl` and `iconPath` return an id's own icon, and `undefined` when it has none. The fallback is yours, in a few lines: walk up the parents in `catalog.json` and take the first id that has an icon.

```ts title="ingredient-icon.ts"
import { GENERIC_ID, iconPath, type CatalogEntry } from "@ingredient-icons/core"
import catalog from "@ingredient-icons/core/catalog.json"

const entries: Record<string, CatalogEntry> = catalog.entries

/** The id whose icon an ingredient shows: its own, its nearest ancestor's (its family's last), or the generic icon. */
export function iconFor(id: string): string {
  const seen = new Set<string>()
  for (let at: string | undefined = id; at !== undefined && !seen.has(at); at = entries[at]?.parent) {
    if (iconPath(at)) return at
    seen.add(at)
  }
  return GENERIC_ID
}
```

That is how <Total /> icons cover <Covered /> of the <CatalogSize /> catalog entries.

```ts
import { iconUrl } from "@ingredient-icons/core"
import { iconFor } from "./ingredient-icon"

iconFor("shallot") // "shallot"
iconFor("extra-virgin-olive-oil") // "olive-oil"
iconFor("cheese-tortelloni") // "pasta"
iconFor("unicorn-steak") // "generic"

const src = iconUrl(iconFor(id))!
```

`iconUrl(iconFor(id))` never returns `undefined`: the generic icon (a cluster of fresh ingredients, under the reserved id `GENERIC_ID`) ships with the others. Pick something else for that case if you prefer: compare `iconFor(id)` with `GENERIC_ID`.

### How the walk works

- **One parent per entry**, so the walk is a straight line: the id, its parent, its parent's parent, up to its family.
- It stops at the **first id that has its own icon**.
- It ends on **the generic icon** when the id is not in the catalog (a typo, an ingredient of your own), or when nothing up to its family has an icon.
- The `seen` set keeps it from looping, should a catalog release ever contain a cycle.

### Telling an approximation apart

`iconFor(id) !== id` when the icon is an ancestor's. Most apps can ignore it: an olive oil bottle for extra virgin olive oil is what people expect. When an approximation would mislead, for example in an allergen list, show only an ingredient's own icon:

```ts
const src = iconUrl(id) // undefined unless the ingredient has its own icon
```

## Catalog releases

The package pins one release of the catalog, exported as `CATALOG_RELEASE` (and `release` in `catalog.json`). New ingredients, new parents and new icons come with new package versions. If you also read the catalog from another source, check in a test that both releases match, so the ids you store are ones the package knows:

```ts
import { CATALOG_RELEASE } from "@ingredient-icons/core"

expect(CATALOG_RELEASE).toBe(myCatalog.release)
```
