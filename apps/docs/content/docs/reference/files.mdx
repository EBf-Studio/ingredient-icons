Both files live at the root of the [repository](https://github.com/EBf-Studio/ingredient-icons). The npm package compiles `manifest.json` into its code and ships `catalog.json` as is (`@ingredient-icons/core/catalog.json`), so you only need to read `manifest.json` [without npm](/docs/guides/without-npm).

## manifest.json

Every icon, keyed by catalog id.

```json title="manifest.json"
{
  "style": 1,
  "sizes": {
    "png": [64, 128, 256, 512],
    "webp": [64, 128, 256]
  },
  "path": "icons/{format}/{size}/{file}.{format}",
  "icons": {
    "shallot": { "file": "shallot" }
  }
}
```

<TypeTable
  type={{
    style: { type: 'number', description: 'Version of the drawing style.' },
    sizes: { type: '{ png: number[]; webp: number[] }', description: 'Sizes available in each format.' },
    path: { type: 'string', description: 'Template of a file\'s path from the repository root.' },
    icons: { type: 'Record<string, { file: string }>', description: 'File name of each id that has its own icon. The file name is the id.' },
  }}
/>

One key is not a catalog id: `"generic": { "file": "generic" }`, the generic icon (a cluster of fresh ingredients) to show for an ingredient the fallback cannot place.

## catalog.json

A snapshot of Marmalade's ingredient catalog: every family and catalog ingredient, by id.

```json title="catalog.json"
{
  "release": "<release>",
  "license": "CC0-1.0",
  "entries": {
    "onion": {
      "parent": "vegetables",
      "family": "vegetables",
      "names": {
        "fr": { "name": "oignon", "synonyms": [] },
        "en": { "name": "onion", "synonyms": ["onions"] },
        "es": { "name": "cebolla", "synonyms": [] }
      }
    },
    "vegetables": {
      "names": {
        "fr": { "name": "légume", "synonyms": [] },
        "en": { "name": "vegetable", "synonyms": ["vegetables", "veggie"] }
      }
    }
  }
}
```

<TypeTable
  type={{
    release: { type: 'string', description: 'Release of the catalog, a hash of its content. The package exports it as CATALOG_RELEASE.' },
    license: { type: '"CC0-1.0"', description: 'The catalog is in the public domain.' },
    entries: { type: 'Record<string, CatalogEntry>', description: 'Every family and catalog ingredient, sorted by id.' },
  }}
/>

### CatalogEntry

<TypeTable
  type={{
    parent: { type: 'string', description: 'The catalog ingredient or family it falls under. Absent on a family.' },
    family: { type: 'string', description: 'The family at the top of its parents. Absent on a family.' },
    names: { type: 'Partial<Record<"fr" | "en" | "es" | "it" | "de" | "pt", { name?: string; synonyms: string[] }>>', description: 'Name and synonyms per language. French and English are reviewed and present on every entry; the others come from Wikidata, where it has them.' },
  }}
/>

A family is an entry with no `parent`. Every other entry has exactly one parent and one family. There are <CatalogSize /> entries in this release, <FamilyCount /> of them families.
